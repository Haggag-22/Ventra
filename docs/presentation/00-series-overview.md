# Ventra walkthrough — series overview

**One slide per step.** Follow this order when demoing Ventra end to end.

| Step | Slide | What happens |
|------|-------|----------------|
| 1 | [01 — Authentication](01-authentication.md) | Connect to AWS, Azure, GCP, or Kubernetes |
| 2 | [02 — Acquire](02-acquire.md) | Pick collectors, scope, and handoff for a new kit |
| 3 | [03 — Collection Kits](03-collection-kits.md) | Save, edit, and reuse kits |
| 4 | [04 — Running a kit](04-running-a-kit.md) | Start a live scan or download an offline kit |
| 5 | [05 — Scans](05-scans.md) | Watch progress, cancel, rerun, open the case |
| 6 | [06 — Cases](06-cases.md) | Investigate timelines, findings, and evidence |
| 7 | [07 — Export](07-export.md) | Ship normalized events to Elastic, Splunk, or NDJSON |
| 8 | [08 — Documentation](08-documentation.md) | IAM, permissions, and collector reference |

## Story in one sentence

**Authenticate → build a kit → run collection → open the case → investigate → export to your SIEM.**

## Who this is for

- Incident responders running first-pass cloud forensics
- IR leads standardizing collection across AWS, Azure, GCP, and Kubernetes
- Anyone onboarding to Ventra’s left-hand **Configuration** and **Documentation** panels
